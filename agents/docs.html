The StoreFront Swarm Protocol

The StoreFront is the world's first fully autonomous, decentralized hardware procurement protocol built on top of the Kite AI Swarm network. It empowers machines and agents to search, negotiate, settle, and secure supply chains without human overhead.

🧬 THE PROTOCOL THESIS

As compute demand skyrockets, agents must be able to acquire their own hardware on-demand. The StoreFront removes standard legacy checkout paths, replacing them with a secure, Stake-to-Deploy, cryptographic marketplace where AI agents negotiate custom checkout terms directly with a merchant agent.

Swarm Architecture

The protocol runs on a highly coordinated, event-driven multi-agent framework powered by LangGraph, Express, and Groq LLMs. The agents cooperate to perform stateful operations:

1. Storefront Manager (The Merchant Agent)

The core API node and gatekeeper of the storefront catalog. It maintains inventory, registers client inquiries, and manages active negotiations based on algorithmic baseline rules.

2. Hardware Procurement Agent (The Buyer)

Spawns autonomously on-demand when a user or client agent requests hardware. It crawls available markets, queries spec matches, and negotiates terms with the merchant agent.

3. CFO & Dynamic Restocker

A background worker agent that continuously tracks market depletion. If stock falls below set thresholds, it queries external wholesale catalogs, performs automated restocks, and signs on-chain settlement receipts using stake pools.

Agent-to-Agent Negotiation

Purchasing goods is no longer static. When you negotiate or trigger a delegated purchase, the buyer agent starts a stateful multi-round negotiation process with the Store Manager:

  • Turn Limits: Every negotiation is hard-capped at 3 rounds to avoid infinite network loops and conserve gas.
  • LLM Validation: The Storefront Manager uses a specialized Groq llama-3.3-70b model configured to protect a target profit margin while evaluating buyer counter-offers.
  • On-Chain Integrity: If an agreement is successfully reached, the finalized price is cryptographically committed, and an on-chain authorization hash is prepared.

On-Chain Attestation Settlement

Every single commerce event is permanently registered on the Kite AI Testnet (Chain ID: 2368) for auditable proof-of-delivery.

The StorefrontAttestation Contract

The active deployment contract: 0xf307f0bfc6ebb291add5a52773fde236c4aeeba7 is the settlement engine. It stores policy hashes, records payments, and issues attestations upon payment resolution.

Kite Passport Identities

To prevent Sybil attacks and secure the protocol against rogue bots, all participating agents must carry a valid, cryptographically verifiable Kite Passport ID.

  • Verification Gate: The StorefrontAttestation contract reverts any incoming settlement transaction if the caller's Passport ID has not been authenticated.
  • Sovereign Security: Passports are cryptographically authenticated on-chain by the deployment owner to establish a secure, whitelist-based environment for the agent swarm.
